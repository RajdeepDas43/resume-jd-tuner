# X-Y-Z: what a bullet should carry

Laszlo Bock's formula, **"Accomplished [X] as measured by [Y], by doing [Z]"**, is a checklist for content, not a sentence template:

- **X:** what the candidate did or delivered.
- **Y:** evidence of scale or result: a number they can explain (the baseline and how it was measured), a scope ("the only engineer on the account"), or an outcome ("the client renewed").
- **Z:** how it was done: the method and the tools actually used. The posting's hard terms belong here when the work really used them.

Write each bullet the way the candidate would explain it to a colleague. If every bullet has the same shape (result, then metric, then "by doing"), the page reads machine-written, so vary the order and the length. One idea per bullet, one to three short sentences, plain past-tense verbs, no em dashes or semicolons.

## Examples

| Weak original | Plain, specific rewrite |
|---|---|
| Responsible for managing servers | Moved 40 on-prem servers to AWS with Terraform. Hosting costs fell 30%, about $120K a year. |
| Worked on the checkout page | Rebuilt the payment form in React and cut load time from 4.1 s to 1.3 s. Checkout conversion rose 12%. |
| Helped with customer support | Set up a Zendesk triage flow that cut first-response time from 9 hours to under 4. |
| Member of data team | Built the Airflow pipeline that loads 2M events a day into Redshift for the daily sales report. |
| Handled social media | Planned and ran the brand's Instagram calendar. Followers grew from 8K to 21K in a year with no paid promotion. |
| Assisted nurses on the ward | Took vitals and charted in Epic for a 28-bed surgical ward on night shifts. |
| Led a team | Led five engineers through a six-month billing migration and finished three weeks early. |

The tools (AWS, Terraform, React, Zendesk, Airflow, Redshift, Epic) appear because the work used them, not to hit a keyword list.

## When the original bullet has no metric

Never invent numbers. In order of preference:

1. **Ask the user** (SKILL.md step 4): "roughly how many users, tickets, patients, accounts?" Estimates the user confirms ("about 50 reports", "a team of four") are fine.
2. **Use scale instead of outcome:** team size, users, volume, number of clients, frequency ("weekly, to 200 engineers").
3. **Use scope:** "the only analyst", "first", "across three product lines".
4. **Drop Y and keep what was done and how.** "Streamlined vendor onboarding by standardizing the contract-review checklist" becomes "Wrote the contract-review checklist that vendor onboarding now follows." An unmeasured true bullet beats a measured fake one.

## Metric hygiene

- Keep a number only if the candidate can explain it in one sentence.
- One metric per clause.
- Don't reuse the same "N+" figure for unrelated things, and don't present someone else's scale (the company's user count) as the candidate's result.
- Prefer modest, specific numbers ("about 83% against an 80% target") to round, impressive ones.
- Six to ten numbers on a page is usually plenty.

## Verbs

Use the plainest true verb. "Led", "owned" and "drove" only if the candidate truly led; otherwise "built", "designed", "ran", "fixed", "set up", "wrote", "sold", "taught". Overclaiming reads as inflation to experienced recruiters and turns into a hard interview question. Vary verbs across a job's bullets, and don't borrow the posting's verbs or adjectives to match it.
